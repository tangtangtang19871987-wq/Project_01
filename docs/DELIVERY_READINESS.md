# 交付就绪性复核（2026-11-01）

## 结论

当前版本可供受控的领域工程师试用：能安装、登录、浏览已发布文本、追溯证据、保存审核、查看研究请求与来源影响。**不能称为已经完成科学验收的知识服务**，也不应把现有发布结论直接当作经专家批准的事实。

## 已修复的交互与安全问题

- 保存审核后重新加载管理页，页顶待审、有效批准和风险计数立即反映新状态。
- 带风险标记的批准在读者页和管理页不再显示为无风险批准，且不计入“Valid approvals”。
- 主题接口的分歧标记与管理页、发布门槛统一使用零起始编号，首条结论的冲突与不一致标记现可同时显示。
- 错误来源解除隔离时，现在也要求受影响结论的批准没有风险标记、自动冲突或未解决分歧；带标记的批准不能解除隔离。
- 服务中断时浏览器收起已缓存的知识内容并自动重试；会话失效后退回登录，侧边栏也不再保留旧发布号。
- 总览明确区分“结构检查通过”和“科学结论已验证”。
- 没有证书时拒绝监听非本机地址，避免局域网登录意外落在明文 HTTP 上。
- 来源影响预览中的英文句子间距及 README 中的英文界面菜单名称已修正。

## 交付门槛

1. **知识准确性：未通过。** 24 条现有结论尚无人工审核，104 处图、公式和版面缺口未核对；书籍 PDF 的其余页不在处理范围。问答的引用定位验证不等于逐句语义支持。领域工程师应先抽查高风险结论、数字、公式及原始图示，并记录批准或问题。
2. **运行交接：待完成。** 目前 Web 不能发起构建或执行 `check`；上传后仍须由操作者运行 CLI、审核候选并发布。交付时要指定这名操作者，并实际走完一次“上传 → 构建 → 审核 → 发布 → 校验”。
3. **恢复能力：部分通过。** 停机复制后的恢复烟测通过，但尚未验证运行中备份、异常中断恢复与跨机器恢复。正式运维需制定一致性备份步骤，覆盖 `raw/`、配置、对象仓、发布指针和三个 SQLite 数据库，并演练错误来源隔离。物理清除旧错误版本的保留政策仍未制定。
4. **可重复发布：待建立。** 项目目录尚无 Git 仓库，也没有已验证的跨机器依赖锁。交给他人前应为代码建立受控版本与发布标签，并把源码包、知识数据、凭据分开发放。现有 `iltkb.json` 指向本机的 `.env` 路径，接收方必须自行配置。
5. **部署验收：待目标环境实测。** 本次仅在本机浏览器与临时副本做烟测；未做异地设备、不同浏览器、长时间并发、断电恢复和安全渗透测试。局域网使用必须配置 HTTPS 或将本机监听置于 HTTPS 反向代理后。

## 建议的第一批试用范围

先限于少量领域工程师，用于浏览原始证据、记录问题和审核候选；明确标注“文本试用、未经领域认证”。交付前完成管理员初始化、独立审核员账号、一次备份恢复演练和目标设备的登录/审核运行测试。对外开放或把结论用于工程决策，应等知识准确性门槛通过后另行评估。
