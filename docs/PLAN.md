# ILT 知识编译器实施计划

硬约束：LangChain/LangGraph 为必要依赖、Gemini API（用户已改选）或本地 Ollama、Markdown/JSON 持久化、无向量化、无数据库。PDF 使用可选 PyMuPDF；图文保留原始快照、页面定位与未处理状态。用户选择先完成文本，Markdown 图片和 PDF 视觉内容登记覆盖缺口。

## 第一阶段：可验证的文件核心

- 不可变原文快照；来源身份与版本分开；逐段覆盖记录。
- 精确摘录与字符位置；结论区分来源陈述、综合推断、冲突。
- 主题候选综合、重要结论语义复核；综合引用仅允许原始证据 ID。
- 来源删除、新反证、重命名、规则变化触发正确增量；单写者、候选版本、原子切换；查询固定版本。
- 分层主题页、中文 n-gram、关键词及别名、相关页面导航。

## 第二阶段：真实 ILT 资料验收（需用户资料和模型）

当前状态：第一阶段文本核心与 CLI 已实现，工程回归测试通过；Gemini API 已增加适配，等待用户资料目录、可用模型和凭据环境变量开展真实领域验收。

建立人工标注问题集：跨论文条件比较、同一实验的多份转述、冲突、新增反证、来源撤回。检查证据支持、原文覆盖、引用准确性、检索召回和调用成本。通过真实领域验收前不宣称知识正确性达标。

## 第三阶段：按实际需要扩展

按主题增加术语及来源关系；资料超出模型上下文时实现分组综合和显式覆盖检查；不增加数据库或向量依赖。

## ILT 条件记录

抽取时记录原文明确给出的波长、NA、照明/偏振、成像近似、掩模模型、光刻胶模型、工艺角、目标版图及数据集、像素/网格与单位、目标函数、求解器、初始化、制造约束、硬件、精度与运行时间。缺失值标记 unknown，禁止用领域常识补齐。跨文档对比先检查这些条件，来源声称的结论不自动提升为普遍事实。

## 发布门槛

机械检查必须全过：来源哈希、覆盖范围、摘录匹配、引用闭合、无生成来源自证、无失效依赖、索引完整。语义复核必须逐结论返回结果，未支持的候选不能发布；复核模型判断仍需人工基准评测。
